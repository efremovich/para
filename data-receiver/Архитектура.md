# Архитектура Data Receiver Service

## Общая архитектура

Проект использует принципы **Clean Architecture** с четким разделением на слои:

```
┌─────────────────────────────────────┐
│      Controller Layer                │
│  (gRPC Gateway, HTTP Handlers)      │
└──────────────┬──────────────────────┘
               │
┌──────────────▼──────────────────────┐
│      Use Cases Layer                 │
│  (Business Logic)                    │
└──────────────┬──────────────────────┘
               │
       ┌───────┴────────┐
       │                │
┌──────▼─────┐  ┌───────▼──────────┐
│ Repository │  │  Web API         │
│   Layer    │  │  (Fetchers)      │
└──────┬─────┘  └───────┬──────────┘
       │                │
       └───────┬────────┘
               │
┌──────────────▼──────────────────────┐
│      Entity Layer                    │
│  (Domain Models)                     │
└──────────────────────────────────────┘
```

## Структура проекта

### 1. `internal/app/` - Инициализация приложения

Основной файл: `app.go`

- Создание и инициализация всех компонентов
- Настройка зависимостей (dependency injection)
- Инициализация репозиториев, API клиентов, брокеров
- Создание основного сервиса `ReceiverCoreService`

### 2. `internal/controller/` - Слой контроллеров

- **`gateway.go`** - gRPC Gateway сервер
- **`api_handlers.go`** - HTTP handlers для REST API
- **`receive_grpc.go`** - gRPC обработчики
- **`router.go`** - маршрутизация HTTP запросов

Обеспечивает:
- gRPC сервер для внутренней коммуникации
- HTTP Gateway для REST доступа
- Swagger документацию
- Middleware для аутентификации и логирования

### 3. `internal/usecases/` - Бизнес-логика

Основной сервис: `service_core.go`

Интерфейс `ReceiverCoreService`:
- `ReceiveCards()` - получение карточек товаров
- `ReceiveWarehouses()` - получение складов
- `ReceiveStocks()` - получение остатков
- `ReceiveOrders()` - получение заказов
- `ReceiveSales()` - получение продаж
- `ReceiveSaleReport()` - получение отчетов о продажах
- И другие методы приема данных

### 4. `internal/usecases/repository/` - Репозитории

Репозитории для работы с PostgreSQL:

- `cardrepo/` - карточки товаров
- `orderrepo/` - заказы
- `salerepo/` - продажи
- `stockrepo/` - остатки
- `warehouserepo/` - склады
- `promotionrepo/` - акции
- И другие (более 30 репозиториев)

Каждый репозиторий:
- Реализует интерфейс для работы с конкретной сущностью
- Использует `postgresdb.QueryExecutor` для выполнения запросов
- Поддерживает транзакции

### 5. `internal/usecases/webapi/` - Клиенты API маркетплейсов

Интерфейс: `interface.go` - `ExtAPIFetcher`

Реализации:
- `wbfetcher/` - Wildberries API клиент
- `ozonfetcher/` - Ozon API клиент
- `yandexfetcher/` - Yandex Market API клиент
- `odincfetcer/` - OdinAss API клиент

Каждый fetcher реализует единый интерфейс `ExtAPIFetcher` с методами:
- `GetCards()`, `GetStocks()`, `GetWarehouses()`, `GetOrders()`, `GetSales()` и др.

### 6. `internal/entity/` - Доменные сущности

32 файла с доменными моделями:
- `card.go` - карточки товаров
- `order.go` - заказы
- `sale.go` - продажи
- `stock.go` - остатки
- `warehouse.go` - склады
- `promotion.go` - акции
- И другие

## Потоки данных

### Получение данных с маркетплейса

```
API Маркетплейса
    ↓
ExtAPIFetcher (wbfetcher/ozonfetcher/yandexfetcher)
    ↓
ReceiverCoreService
    ↓
Repository Layer
    ↓
PostgreSQL
```

### Обработка через брокер

```
NATS Consumer
    ↓
ReceiverCoreService
    ↓
ExtAPIFetcher
    ↓
Repository Layer
    ↓
PostgreSQL
    ↓
NATS Publisher (уведомления)
```

## Брокер сообщений (NATS)

- **Consumer** - получение задач на обработку данных
- **Publisher** - отправка уведомлений о завершении обработки
- Настройки очереди: workers, max deliver, ack wait, nak timeout

## Особенности архитектуры

1. **Единый интерфейс** для всех маркетплейсов через `ExtAPIFetcher`
2. **Разделение чтения/записи** БД через writer/reader connections
3. **Raw Layer** - кэширование сырых данных от API маркетплейсов
4. **Трейсинг** - интеграция с Jaeger для отслеживания запросов
5. **Метрики** - сбор метрик через Prometheus
6. **Graceful shutdown** - корректное завершение работы сервиса
