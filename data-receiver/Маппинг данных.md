# Маппинг данных из API маркетплейсов в Entity

## Обзор

Документ описывает, как данные из различных API маркетплейсов преобразуются в единые доменные сущности (`entity.*`). Каждый маркетплейс имеет свою структуру данных, но все они маппятся в единую модель.

## Структура маппинга

```
API Маркетплейса (WB/Ozon/Yandex)
    ↓
Структуры ответа API (wbfetcher.Cards, ozonfetcher.Items, yandexfetcher.OrderInfo)
    ↓
Методы конвертации (convert*ToEntity)
    ↓
Доменные сущности (entity.Card, entity.Order, entity.Sale, etc.)
```

## Wildberries (wbfetcher)

### Card → entity.Card

**Источник:** `POST /content/v2/get/cards/list`

**Структура ответа:** `wbfetcher.Cards`

| API поле | entity.Card поле | Примечание |
|----------|------------------|------------|
| `NmID` | `ExternalID` | ID товара WB |
| `VendorCode` | `VendorID`, `VendorCode` | Парсинг через regex `\d{2}-\d{5,8}` |
| `Title` | `Title` | Название товара |
| `Description` | `Description` | Описание (только из API, не из raw layer) |
| `Brand` | `Brand.Title` | Бренд |
| `SubjectName` | `Categories[0].Title` | Категория |
| `Photos[].Big` | `MediaFile[].Link` | Фото (TypeID=1) |
| `Video` | `MediaFile[].Link` | Видео (TypeID=2) |
| `Dimensions` | `Dimension` | Габариты (Width, Height, Length, IsValid) |
| `Characteristics[]` | `Characteristics[]` | Характеристики (Name → Title, Value → Value[]) |
| `Sizes[].TechSize` | `Sizes[].TechSize` | Технический размер |
| `Sizes[].WbSize` | `Sizes[].Title` | Размер WB |
| `Sizes[].ChrtID` | `Sizes[].ExternalID` | ID размера |
| `Sizes[].Skus[]` | `Barcodes[].Barcode` | Штрихкоды из размеров |
| `UpdatedAt` | `UpdatedAt` | Дата обновления |

**Особенности:**
- VendorCode парсится через regex для извлечения формата `XX-XXXXXXX`
- Каждый размер создает отдельные записи Size и Barcode
- Характеристики конвертируются из `any` в `[]string` через `convertInterfaceToStringSlice()`

## Ozon (ozonfetcher)

### Card → entity.Card

**Источник:** 
1. `POST /v2/product/list` - список товаров
2. `POST /v2/product/info/list` - информация о товарах
3. `POST /v2/product/info/attributes` - атрибуты товаров
4. `POST /v1/product/info/description` - описание категорий

**Структура ответа:** `ozonfetcher.AttributeMeta` (комбинированные данные)

| API поле | entity.Card поле | Примечание |
|----------|------------------|------------|
| `ID` | `ExternalID` | ID товара Ozon |
| `Name` | `Title` | Название товара |
| `OfferID` | `VendorID`, `VendorCode` | Парсинг через `getMetaFromVendorID()` |
| `DescriptionCategoryID` | `Categories[].ExternalID` | ID категории |
| `Width`, `Height`, `Depth` | `Dimension` | Габариты |
| `Barcode` | `Barcodes[].Barcode` | Штрихкод |
| `Images[]` | `MediaFile[].Link` | Фото (TypeID=1) |
| `Attributes[].AttributeID == 31` | `Brand.Title` | Бренд (ID=31) |
| `Attributes[].Name == "Аннотация"` | `Description` | Описание |
| `Attributes[].Values[].Value` | `Characteristics[].Value[]` | Характеристики |
| `Attributes[].Name` | `Characteristics[].Title` | Название характеристики |
| `OfferID` (парсинг) | `Sizes[].TechSize`, `Sizes[].Title` | Размер из offerID |

**Особенности:**
- `getMetaFromVendorID()` парсит offerID в формате `RBB-061/00-0014881/58`:
  - `vendorCode/vendorID/size` → vendorCode, vendorID, size
  - `vendorID/size` → vendorID, vendorID, size
  - `vendorID` → vendorID, vendorID, "One size"
- Категории получаются из отдельного запроса и маппятся по `DescriptionCategoryID`
- Характеристики фильтруются: бренд и описание обрабатываются отдельно

### Stock → entity.StockMeta

**Источник:**
1. Raw layer `ozon.product_stocks` + `ozon.product_info_list` + `ozon.product_info_stocks`
2. `POST /v3/supply/list` → `POST /v3/supply/get` → `POST /v3/supply/bundle` - остатки через поставки

**Структура ответа:** `ozonfetcher.dbStock` или `ozonfetcher.BundleItems`

| API поле | entity.StockMeta поле | Примечание |
|----------|----------------------|------------|
| `ProductID` | `Seller2Card.ExternalID` | ID товара |
| `OfferID` | `Card.VendorCode`, `Card.VendorID` | Парсинг |
| `WarehouseID` | `Warehouse.ExternalID` | ID склада |
| `WarehouseName` | `Warehouse.Title` | Название склада |
| `Barcodes` | `Barcode.Barcode` | Штрихкоды (парсинг из строки) |
| `ValidStockCount` + другие | `Stock.Quantity` | Сумма всех типов остатков |
| `Price` | `PriceSize.Price` | Цена |
| `OldPrice` | `PriceSize.PriceWithoutDiscount` | Старая цена |
| `MarketingPrice` | `PriceSize.PriceFinal` | Маркетинговая цена |
| `DateReport` | `Stock.CreatedAt` | Дата отчета |
| `OfferID` (парсинг) | `Size.TechSize` | Размер |

**Особенности:**
- Quantity = сумма всех типов остатков (valid, excess, expiring, other, return, defect, transit, waiting)
- Пропускаются записи с `WarehouseID = 0`
- Barcodes парсятся из строки формата `{barcode1,barcode2}`
- Из API остатки получаются через цепочку: список поставок → данные поставок → бандлы с остатками

## Общие паттерны маппинга

### Парсинг VendorCode/VendorID

Все маркетплейсы парсят артикулы по-разному:

- **WB:** Regex `\d{2}-\d{5,8}` для извлечения формата `XX-XXXXXXX`
- **Ozon:** Парсинг через `/` или `-` в формате `vendorCode/vendorID/size`
- **Yandex:** Парсинг через `/` или `-` в формате `prefix/vendorCode/size` или `vendorCode-size`

### Извлечение размера

- **WB:** Из поля `Sizes[].TechSize`
- **Ozon:** Из `OfferID` через парсинг (последняя часть после `/`)
- **Yandex:** Из `OfferID` через `extractSizeFromOfferID()` или из характеристик

### Обработка цен

Все маркетплейсы маппят цены в `PriceSize`:
- `Price` - цена со скидкой/текущая цена
- `PriceWithoutDiscount` - цена без скидки/старая цена
- `PriceFinal` - итоговая цена/выплата

### Связи между сущностями

- **Order/Sale → Card:** Через `Card.ExternalID` и `Card.VendorCode`
- **Order/Sale → Warehouse:** Через `Warehouse.ExternalID` или `Warehouse.Title`
- **Order/Sale → Region:** Создается структура с RegionName, District, Country
- **StockMeta → Card:** Через `Card.VendorCode` и `Card.VendorID`
- **StockMeta → Warehouse:** Через `Warehouse.ExternalID`
