# Инфраструктура Data Receiver Service

## База данных

### PostgreSQL

Проект использует PostgreSQL как основное хранилище данных.

**Подключения:**
- **Writer** - для записи данных (основная БД)
- **Reader** - для чтения данных (может быть реплика для распределения нагрузки)
- **Raw Layer Writer/Reader** - отдельная БД для кэширования сырых данных от API маркетплейсов

**Библиотека:** `github.com/jackc/pgx/v5` - драйвер PostgreSQL для Go

**Управление соединениями:** `pkg/postgresdb/` - обертка для работы с пулом соединений

### Миграции

**Инструмент:** Goose (`github.com/pressly/goose/v3`)

**Расположение:** `migrations/data_base/`

**Команды:**
```bash
# Создание новой миграции
make create-migration name=init_db

# Применение миграций
make migrate-up PG_USER=user PG_PASSWORD=pass PG_DBNAME=db PG_HOST=localhost PG_PORT=5432
```

Миграции применяются автоматически при старте приложения или вручную через команды.

## Мониторинг

### Prometheus

**Библиотека:** `github.com/prometheus/client_golang`

**Метрики:**
- Счетчики запросов
- Гистограммы времени выполнения
- Gauge метрики состояния

**Реализация:** `pkg/metrics/` и `pkg/ametrics/`

**Эндпоинт:** `/metrics` (стандартный Prometheus endpoint)

### Grafana

**Конфигурация:**
- `infra/grafana-datasource.yml` - настройка источника данных
- `infra/grafana-provisioning.yml` - провижининг дашбордов
- `infra/grafana-dashboard.json` - дашборд для визуализации метрик

**Настройка:** См. `infra/GRAFANA_SETUP.md`

## Трейсинг

### Jaeger

**Библиотека:** `github.com/uber/jaeger-client-go`

**Реализация:** `pkg/jaeger/`

**Конфигурация:**
- `JAEGER_COLLECTOR` - URL коллектора Jaeger
- Автоматическая инструментация gRPC через OpenTelemetry

**Использование:**
- Трейсинг всех запросов к API
- Отслеживание цепочек вызовов между сервисами
- Анализ производительности

## Брокер сообщений

### NATS

**Библиотека:** `github.com/nats-io/nats.go`

**Реализация:**
- `pkg/broker/brokerconsumer/` - потребитель сообщений
- `pkg/broker/brokerpublisher/` - издатель сообщений

**Использование:**
- Асинхронная обработка задач на получение данных
- Уведомления о завершении обработки
- Очереди для распределения нагрузки

**Настройки очереди:**
- Workers - количество воркеров
- Max Deliver - максимальное количество попыток
- Ack Wait - время на обработку сообщения
- NAK Timeout - таймаут перед повторной попыткой

## Логирование

### Структурированное логирование

**Библиотека:** `github.com/rs/zerolog`

**Реализация:** `pkg/alogger/`

**Особенности:**
- Структурированные логи в JSON формате
- Уровни логирования: Debug (-4), Info (0), Warn (4), Error (8)
- Контекстное логирование через context
- Middleware для HTTP и gRPC

**Уровни:**
- `-4` - Debug (детальная отладочная информация)
- `0` - Info (обычная информация)
- `4` - Warn (предупреждения)
- `8` - Error (ошибки)

## Безопасность

### Аутентификация

- HTTP Gateway использует токен аутентификации
- Токен передается через заголовок `Authorization: Bearer {token}`

### Безопасность БД

- Подключения к БД через SSL (настраивается через `sslmode`)
- Разделение прав доступа через writer/reader соединения

## Масштабирование

### Горизонтальное масштабирование

- Статeless архитектура позволяет запускать несколько экземпляров
- NATS обеспечивает распределение нагрузки между экземплярами
- PostgreSQL репликация для чтения

### Вертикальное масштабирование

- Настройка пула соединений к БД
- Настройка количества воркеров очереди
- Настройка таймаутов и лимитов
