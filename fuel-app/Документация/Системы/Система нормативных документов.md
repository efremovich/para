# Система нормативных документов

## Обзор

Система нормативных документов включает одну таблицу:
- `regulatory_documents` - хранит информацию о нормативных документах (устав, оферта и т.д.)

## Таблица regulatory_documents

Таблица хранит информацию о нормативных документах (устав, оферта и т.д.).

**Поля:**
- `id` - UUID, первичный ключ
- `company_id` - UUID, внешний ключ на таблицу companies
- `organization_id` - UUID, внешний ключ на таблицу organizations
- `document_type` - текст, тип документа (устав, оферта и т.д.), возможные значения: 'charter', 'offer', 'contract', 'policy', 'regulation', 'manual', 'procedure', 'instruction'
- `title` - текст, название документа
- `description` - текст, описание документа
- `file_path` - текст, ссылка на файл документа
- `file_name` - текст, имя файла документа
- `file_size` - bigint, размер файла в байтах
- `file_type` - текст, тип файла (MIME type)
- `version` - текст, версия документа
- `is_active` - boolean, действующая ли версия документа (по умолчанию TRUE)
- `effective_date` - дата вступления в силу
- `expiry_date` - дата окончания действия
- `created_at` - дата создания
- `updated_at` - дата обновления
- `deleted_at` - дата удаления (для мягкого удаления)

## Работа системы

### 1. Создание нормативного документа

- Документ создается и привязывается к конкретной компании (и, опционально, к организации)
- Документ должен иметь тип, название и путь к файлу
- Можно указать версию, даты вступления в силу и окончания действия
- Можно отметить документ как действующий

## Примеры использования

### Создание устава компании:

```sql
INSERT INTO regulatory_documents (company_id, organization_id, document_type, title, description, file_path, file_name, file_size, version, is_active, effective_date)
VALUES ('[ID компании]', '[ID организации]', 'charter', 'Устав ООО "Ромашка"', 'Устав общества с ограниченной ответственностью', '/uploads/docs/charter.pdf', 'charter.pdf', 1572864, '1.0', TRUE, '2023-01-01');
```

### Создание оферты:

```sql
INSERT INTO regulatory_documents (company_id, organization_id, document_type, title, description, file_path, file_name, file_size, version, is_active, effective_date, expiry_date)
VALUES ('[ID компании]', '[ID организации]', 'offer', 'Публичная оферта на заключение договора', 'Публичная оферта на поставку топлива', '/uploads/docs/offer.pdf', 'offer.pdf', 2048576, '2.1', TRUE, '2023-06-01', '2024-05-31');
```

### Получение всех действующих документов компании:

```sql
SELECT id, title, document_type, file_name, version, effective_date, expiry_date
FROM regulatory_documents
WHERE company_id = '[ID компании]'
  AND is_active = TRUE
  AND deleted_at IS NULL
ORDER BY document_type, effective_date DESC;
```

### Получение документов определенного типа:

```sql
SELECT title, file_path, description, version, effective_date
FROM regulatory_documents
WHERE company_id = '[ID компании]'
  AND document_type = 'charter'
  AND deleted_at IS NULL
ORDER BY effective_date DESC;
```

### Получение устава компании:

```sql
SELECT title, file_path, description, version, effective_date
FROM regulatory_documents
WHERE company_id = '[ID компании]'
  AND document_type = 'charter'
  AND is_active = TRUE
  AND deleted_at IS NULL
LIMIT 1;
```

### Получение просроченных документов:

```sql
SELECT title, document_type, expiry_date
FROM regulatory_documents
WHERE company_id = '[ID компании]'
  AND expiry_date < CURRENT_DATE
  AND is_active = TRUE
  AND deleted_at IS NULL;
```

## Особенности

- Каждый документ обязательно связан с компанией, и опционально - с организацией
- Используется проверочное ограничение для типов документов
- Поддержка версионности документов
- Поддержка дат вступления в силу и окончания действия
- Поле is_active позволяет отслеживать действующие версии документов
- Используется мягкое удаление для сохранения исторических версий
- Поддержка метаданных файлов (размер, MIME тип)
- Индексы по ключевым полям для эффективного поиска
- Возможность отслеживания актуальности документов по датам
