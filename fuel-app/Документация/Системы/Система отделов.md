# Система отделов и подразделений

## Обзор

Система отделов и подразделений включает две таблицы:
1. `departments` - хранит информацию об отделах и подразделениях
2. `department_cards` - связывает отделы и карты (многие ко многим)

## Таблицы

### 1. departments

Таблица хранит информацию об отделах и подразделениях, связанных с компаниями.

**Поля:**
- `id` - UUID, первичный ключ
- `company_id` - UUID, внешний ключ на таблицу companies
- `name` - текст, название отдела/подразделения
- `code` - текст, код отдела/подразделения
- `description` - текст, описание отдела/подразделения
- `parent_id` - UUID, внешний ключ на саму таблицу departments (для иерархии подразделений)
- `created_at` - дата создания
- `updated_at` - дата обновления
- `deleted_at` - дата удаления (для мягкого удаления)

### 2. department_cards

Промежуточная таблица, которая связывает отделы и карты.

**Поля:**
- `id` - UUID, первичный ключ
- `department_id` - UUID, внешний ключ на таблицу departments
- `card_id` - UUID, внешний ключ на таблицу cards
- `created_at` - дата создания
- `updated_at` - дата обновления
- `deleted_at` - дата удаления (для мягкого удаления)

## Работа системы

### 1. Создание отдела/подразделения

- Отдел создается внутри компании (через внешний ключ `company_id`)
- Может быть иерархическим (через `parent_id` - ID родительского подразделения)
- Может иметь код и описание для дополнительной информации

### 2. Связывание отделов и карт

- Через таблицу `department_cards` можно связать карты с отделами
- Одна карта может быть привязана к одному или нескольким отделам
- Один отдел может использовать одну или несколько карт

## Примеры использования

### Создание отдела:

```sql
INSERT INTO departments (company_id, name, code, description)
VALUES ('[ID компании]', 'Отдел продаж', 'sales', 'Отдел по работе с клиентами и продажам');
```

### Создание подразделения (дочернего отдела):

```sql
INSERT INTO departments (company_id, name, code, description, parent_id)
VALUES ('[ID компании]', 'Группа по работе с VIP-клиентами', 'vip_sales', 'Группа по работе с важными клиентами', '[ID родительского отдела]');
```

### Привязка карты к отделу:

```sql
INSERT INTO department_cards (department_id, card_id)
VALUES ('[ID отдела]', '[ID карты]');
```

### Получение всех карт, привязанных к отделу:

```sql
SELECT c.number, c.holder, c.is_virtual
FROM cards c
JOIN department_cards dc ON c.id = dc.card_id
WHERE dc.department_id = '[ID отдела]'
  AND dc.deleted_at IS NULL
  AND c.deleted_at IS NULL;
```

### Получение всех подразделений компании:

```sql
SELECT id, name, code, description
FROM departments
WHERE company_id = '[ID компании]'
  AND deleted_at IS NULL
ORDER BY name;
```

### Получение всех карт, привязанных к отделу и всем его подразделениям (рекурсивный запрос):

```sql
WITH RECURSIVE dept_hierarchy AS (
  -- Начинаем с конкретного отдела
  SELECT id, parent_id
  FROM departments
  WHERE id = '[ID корневого отдела]'
    AND deleted_at IS NULL

  UNION ALL

  -- Добавляем дочерние подразделения
  SELECT d.id, d.parent_id
  FROM departments d
  JOIN dept_hierarchy dh ON d.parent_id = dh.id
  WHERE d.deleted_at IS NULL
)
SELECT c.number, c.holder, d.name as department_name
FROM cards c
JOIN department_cards dc ON c.id = dc.card_id
JOIN departments d ON dc.department_id = d.id
JOIN dept_hierarchy dh ON d.id = dh.id
WHERE dc.deleted_at IS NULL
  AND c.deleted_at IS NULL;
```

## Особенности

- Поддержка иерархии подразделений через поле `parent_id`
- Связь с компаниями обеспечивает изоляцию отделов по компаниям
- Связь с картами позволяет управлять тем, какие карты используются в конкретных отделах
- Используется мягкое удаление для сохранения целостности исторических данных
- Таблица `department_cards` имеет уникальное ограничение, чтобы предотвратить дублирование связей
- Возможность рекурсивного запроса для получения всех подразделений отдела
