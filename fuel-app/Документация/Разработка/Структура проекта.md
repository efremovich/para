# Структура проекта fuel-app-backend

## Обзор

Fuel App Backend - это микросервис на Go для управления топливными картами, транзакциями, компаниями и пользователями. Проект использует gRPC и HTTP REST API через grpc-gateway, PostgreSQL в качестве базы данных и следует архитектуре Clean Architecture.

## Архитектура

### Clean Architecture

Проект следует принципам Clean Architecture с разделением на слои:

1. **Entity Layer** (`internal/entity/`) - Доменные сущности, бизнес-правила
2. **Use Case Layer** (`internal/usecase/`) - Бизнес-логика приложения
3. **Repository Layer** (`internal/repository/`) - Абстракция доступа к данным
4. **Controller Layer** (`internal/controller/`) - Обработка HTTP/gRPC запросов
5. **Infrastructure Layer** (`internal/service/`) - Внешние сервисы (БД, хранилище, метрики)

### Основные компоненты

#### API Layer
- **gRPC** - основной протокол для внутренней коммуникации
- **HTTP REST** - через grpc-gateway для внешних клиентов
- **Swagger/OpenAPI** - автоматически генерируемая документация

#### Data Layer
- **PostgreSQL** - основная база данных
- **S3** - хранилище файлов (документы, изображения)
- **Миграции** - управление схемой БД через SQL миграции

#### Security
- **JWT токены** - аутентификация и авторизация
- **RBAC** - управление ролями и правами доступа
- **Refresh tokens** - обновление access токенов

#### Observability
- **Prometheus** - метрики приложения
- **OpenTelemetry** - трейсинг запросов
- **Structured logging** - структурированное логирование

## Основные сервисы API

### AuthService
- Авторизация пользователей (email/phone + password)
- Регистрация новых пользователей и компаний
- Обновление токенов
- Выход из системы

### UserService
- Управление пользователями
- Статусы пользователей
- Устройства пользователей (FCM токены)

### CardService
- Управление топливными картами
- Привязка карт к пользователям
- Фильтрация карт

### CompanyService
- Управление компаниями
- Поиск по ИНН
- CRUD операции

### TransactionService
- Управление транзакциями
- Фильтрация по различным параметрам
- Пагинация результатов

### Другие сервисы
- ContactService - контакты
- ContractService - контракты
- DepartmentService - отделы
- DocumentService - документы
- EmitentService - эмитенты карт

- OfficeService - офисы
- OrganizationService - организации

## Разработка

### Требования
- Go 1.24.6+
- PostgreSQL
- Docker и Docker Compose (для локальной разработки)
- Protobuf компилятор

### Основные команды (Makefile)

```bash
# Генерация API из proto файлов
make generate-api

# Запуск линтера
make lint

# Локальный запуск через Docker Compose
make local-up

# Запуск тестов
make test-local

# Генерация моков
make generate-mocks

# Генерация переменных окружения из структуры конфигурации
make gen-envs
```

### Локальная разработка

1. Клонировать репозиторий
2. Настроить переменные окружения в `config/local.env`
3. Запустить через Docker Compose: `make local-up`
4. API будет доступно на `http://localhost:8080`
5. Swagger документация: `http://localhost:8080/swagger`

## Тестирование

- **Unit тесты** - тесты отдельных компонентов
- **Integration тесты** - тесты с реальной БД (требуют тег `integration`)
- **E2E тесты** - end-to-end тесты API

Запуск:
```bash
make test-local              # Unit тесты
make test-integration        # Integration тесты
```
