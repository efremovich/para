## Реализация rate limiting для эндпоинтов Contacts

### Структура и переменные
- Создана структура `rateLimiterEntry` с полями `tokens`, `lastRefill`, `mutex`
- Добавлены переменные `contactsRateLimiters` и `contactsRateLimitersMutex`
- Определены константы:
  - `contactsRateLimitPeriod = 1 * time.Minute`
  - `contactsRateLimitMaxRequests = 300`
  - `contactsRateLimitInterval = 200 * time.Millisecond`
  - `contactsRateLimitBurst = 20`
  - `contactsRateLimit409Weight = 5`
  - `contactsRateLimitRefillRate = 5.0` (токенов/сек)

### Функции rate limiting
- `isContactsEndpoint(url string) bool` - проверка эндпоинтов Contacts
- `getRateLimiterForUser(userID string) *rateLimiterEntry` - получение/создание rate limiter
- `refillTokens(limiter *rateLimiterEntry)` - пополнение токенов по алгоритму token bucket
- `checkRateLimit(limiter *rateLimiterEntry, weight int)` - проверка лимита и потребление токенов
- `getUserIDForRateLimit(r *http.Request, remoteIP string) string` - извлечение user ID (приоритет: guid -> gate -> remote IP)
- `statusCaptureWriter` - обертка для перехвата статус кода ответа

### Интеграция в Register
- Проверка rate limit перед выполнением функции для эндпоинтов Contacts
- Возврат 429 с заголовками `X-Ratelimit-*` при превышении лимита
- Обновление rate limiter после выполнения функции с учетом веса ответа (409 = 5 токенов)
- Добавление заголовка `X-Ratelimit-Remaining` во все ответы

### Модификация функций ответа
- `returnError` - добавлена обработка ошибки 429 с заголовками `X-Ratelimit-Retry`, `X-Ratelimit-Reset`, `X-Ratelimit-Limit`
- Заголовок `X-Ratelimit-Remaining` добавляется для всех ответов эндпоинтов Contacts

### Эндпоинты под rate limiting
- `/invoice/contacts/get_contacts`
- `/invitations/contacts`
