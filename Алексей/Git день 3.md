**Интерактивный rebase** (`git rebase -i`) — один из самых мощных инструментов Git.  
Он позволяет **редактировать историю коммитов** вашей ветки: менять порядок, объединять, переписывать сообщения, удалять и даже останавливаться на коммите, чтобы поправить код.

---

### 1. Как запустить

```bash
# Перебазировать последние N коммитов
git rebase -i HEAD~N

# Перебазировать все коммиты текущей ветки, которых нет в main
git rebase -i main

# Перебазировать начиная с конкретного коммита
git rebase -i <hash-коммита>
```

После запуска откроется редактор (обычно Vim или nano) со списком коммитов.

---

### 2. Как выглядит окно интерактивного rebase

Пример:

```
pick 7a3f9c2 Add login form
pick 2b8e1d4 Fix button styles
pick 9c4a7e1 Add validation
pick 5f2d8b3 Update README

# Rebase 7a3f9c2..5f2d8b3 onto main
#
# Commands:
# p, pick   = использовать коммит как есть
# r, reword = использовать коммит, но изменить сообщение
# e, edit   = использовать коммит, но остановиться для правок
# s, squash = объединить с предыдущим коммитом (оставить оба сообщения)
# f, fixup  = объединить с предыдущим, выбросить сообщение этого коммита
# d, drop   = удалить коммит
# ...
```

Коммиты идут **от старых к новым** (сверху вниз).

---

### 3. Основные команды (что можно делать)

| Команда   | Сокращение | Что делает                                      | Когда использовать |
|-----------|------------|--------------------------------------------------|--------------------|
| `pick`    | `p`        | Оставить коммит без изменений                    | По умолчанию |
| `reword`  | `r`        | Оставить коммит, но изменить сообщение           | Исправить опечатку в сообщении |
| `edit`    | `e`        | Остановиться на этом коммите                     | Поправить код или разбить коммит |
| `squash`  | `s`        | Объединить с предыдущим + оставить оба сообщения | Склеить несколько коммитов |
| `fixup`   | `f`        | Объединить с предыдущим + выбросить сообщение    | Убрать "fix", "wip", "typo" |
| `drop`    | `d`        | Полностью удалить коммит                         | Убрать ненужный коммит |
| `break`   | `b`        | Просто остановиться (без изменений)              | Редко |

### 4. Самые частые сценарии

#### 4.1. Объединить несколько коммитов в один (squash / fixup)

Было:
```
pick 7a3f9c2 Add login form
pick 2b8e1d4 Fix button styles
pick 9c4a7e1 Add validation
pick 5f2d8b3 Update README
```

Хотим оставить только один красивый коммит:

```
pick 7a3f9c2 Add login form
fixup 2b8e1d4 Fix button styles
fixup 9c4a7e1 Add validation
fixup 5f2d8b3 Update README
```

Или через `squash`, если хотите отредактировать итоговое сообщение.

#### 4.2. Изменить сообщение коммита

```
reword 7a3f9c2 Add login form
```

После сохранения Git откроет редактор, где можно переписать сообщение.

#### 4.3. Изменить порядок коммитов

Просто поменяйте строки местами:

```
pick 9c4a7e1 Add validation
pick 7a3f9c2 Add login form
pick 2b8e1d4 Fix button styles
```

#### 4.4. Удалить коммит

```
drop 5f2d8b3 Update README
```
или просто удалите строку.

#### 4.5. Остановиться и поправить код (`edit`)

```
edit 7a3f9c2 Add login form
```

Git остановится на этом коммите. Дальше:

```bash
# вносите изменения
git add .
git commit --amend          # обновить текущий коммит
# или
git commit                  # создать новый коммит (разбить)

git rebase --continue       # продолжить
```

---

### 5. Как работать с конфликтами

Во время rebase конфликты решаются **по одному коммиту**.

Когда возникает конфликт:

```bash
# 1. Смотрим, что конфликтует
git status

# 2. Правим файлы
# 3. Добавляем исправленные файлы
git add .

# 4. Продолжаем
git rebase --continue
```

Если хотите полностью отменить rebase:

```bash
git rebase --abort
```

---

### 6. Важные правила безопасности

1. **Делайте интерактивный rebase только на своей личной ветке**, которую ещё никто не использует (или вы единственный, кто с ней работает).
2. После rebase хеши коммитов меняются → обычный `git push` не сработает. Нужно:
   ```bash
   git push --force-with-lease
   ```
3. Перед сложным rebase можно создать резервную ветку:
   ```bash
   git branch backup-feature
   ```
4. Если что-то пошло совсем плохо — `git reflog` почти всегда спасает.

---

### 7. Полезные приёмы

```bash
# Быстро объединить последние 3 коммита
git rebase -i HEAD~3

# Автоматически использовать fixup для коммитов с сообщением "fixup!"
git commit --fixup <hash>
git rebase -i --autosquash main
```

---

**Краткий итог:**

Интерактивный rebase — это «хирургия» истории.  
Самое частое применение:
- почистить ветку перед Pull Request (убрать «wip», «fix», «typo»);
- сделать историю красивой и понятной;
- исправить сообщения коммитов.
