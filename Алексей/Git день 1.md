**Доклад: Введение в Git — система контроля версий**

### 1. Что такое Git и зачем он нужен

**Git** — это распределённая система контроля версий (Version Control System).  
Она позволяет отслеживать изменения в файлах проекта, возвращаться к предыдущим версиям, работать в команде и не бояться «сломать» код.

**Главные проблемы, которые решает Git:**
- «У меня было 15 папок: `project_final`, `project_final2`, `project_really_final`…»
- Кто-то случайно удалил важный файл.
- Несколько человек правят один и тот же файл и затирают работу друг друга.
- Нужно понять, кто и когда внёс изменение.
- Хочется безопасно экспериментировать с кодом.

**Коротко:** Git — это «машина времени» + «совместный блокнот» для кода (и не только).

### 2. Основные понятия (обязательно понять)

| Понятие          | Простое объяснение                                      | Аналогия                          |
|------------------|---------------------------------------------------------|-----------------------------------|
| **Репозиторий**  | Папка проекта, за которой следит Git                    | Папка с историей всех версий      |
| **Коммит**       | Снимок состояния файлов в определённый момент           | Сохранённая точка в игре          |
| **Ветка (branch)** | Независимая линия разработки                          | Параллельная вселенная проекта    |
| **HEAD**         | Указатель на текущий коммит, в котором ты находишься    | Ты сейчас стоишь здесь            |
| **Staging area** (индекс) | Промежуточная зона: файлы, которые попадут в следующий коммит | Корзина перед кассой             |
| **Удалённый репозиторий** | Копия репозитория на сервере (GitHub, GitLab и т.д.) | Облачное хранилище               |

### 3. Установка и первая настройка

1. Скачать Git: https://git-scm.com  
2. После установки открыть терминал (или Git Bash на Windows) и выполнить:

```bash
git config --global user.name "Имя Фамилия"
git config --global user.email "email@example.com"
```

Проверить настройки:
```bash
git config --list
```

### 4. Базовый рабочий цикл (самое важное)

```bash
# 1. Создать новый репозиторий или клонировать существующий
git init                    # в пустой папке
# или
git clone https://github.com/user/repo.git

# 2. Посмотреть статус
git status

# 3. Добавить файлы в staging area
git add файл.txt            # один файл
git add .                   # все изменения
git add -p                  # интерактивно (очень полезно)

# 4. Сделать коммит
git commit -m "Краткое понятное описание изменений"

# 5. Посмотреть историю
git log --oneline --graph --all
```

**Хорошие сообщения коммитов:**
- `Add user authentication`
- `Fix crash when opening empty file`
- `Update README with installation steps`

Плохие: `fix`, `asdf`, `изменения`, `работаю дальше`.

### 5. Работа с ветками (основа современной разработки)

```bash
git branch                  # список веток
git branch feature/login    # создать ветку
git switch feature/login    # переключиться на неё (или git checkout)
git switch -c feature/login # создать и сразу переключиться

# Когда закончил работу в ветке:
git switch main
git merge feature/login     # влить изменения в main
```

**Правило:**  
`main`/`master` — всегда рабочая версия.  
Новые фичи и эксперименты — только в отдельных ветках.

### 6. Работа с удалённым репозиторием (GitHub / GitLab / Bitbucket)

```bash
# Первый раз
git remote add origin https://github.com/user/repo.git
git push -u origin main

# Обычная работа
git push                    # отправить свои коммиты
git pull                    # забрать чужие изменения + слить
git fetch                   # только забрать, без слияния
```

**Типичный сценарий на каждый день:**
1. `git pull`
2. Создать ветку → работать → коммитить
3. `git push`
4. Создать Pull Request / Merge Request
5. После ревью — влить в `main`

### 7. Полезные команды «на каждый день»

```bash
git status                  # что происходит прямо сейчас
git diff                    # что изменилось (ещё не добавлено)
git diff --staged           # что уже в staging
git log --oneline -10       # последние 10 коммитов
git restore файл.txt        # отменить изменения в файле (до add)
git restore --staged файл.txt  # убрать из staging
git commit --amend          # исправить последний коммит (только если ещё не пушили!)
```

### 8. Что обязательно запомнить новичку

1. **Коммить часто**, маленькими осмысленными кусками.
2. **Никогда** не коммить секреты (пароли, API-ключи) — используй `.gitignore`.
3. Перед тем как начать новую задачу — `git pull`.
4. Не бойся веток — они почти ничего не стоят.
5. `git status` — твоя лучшая подруга. Смотри её постоянно.
6. Если что-то сильно сломал — почти всегда можно откатиться (`git reflog` — «чёрный ящик»).

### 9. Минимальный `.gitignore` (пример)

```
node_modules/
.env
*.log
.DS_Store
dist/
build/
__pycache__/
```

### 10. План занятия «завтра» (рекомендуемый)

1. **15 мин** — теория + аналогии (что такое Git).
2. **10 мин** — установка + настройка имени/почты.
3. **20 мин** — создаём папку → `git init` → правим файлы → `add` → `commit` → смотрим `log`.
4. **15 мин** — ветки: создаём, переключаемся, мержим.
5. **20 мин** — регистрируемся на GitHub, создаём репозиторий, делаем `push` и `pull`.
6. **10 мин** — разбираем типичные ошибки и как из них выходить.
